# Motion & physics

The fun in pixel3d-ui comes from how things respond to touch, not from decoration. Every interactive sticker follows the same physics, so the whole kit feels like one material.

<Rule name="Peel">Hover lifts a sticker 5px, straightens it to 0° and scales it to 1.04 with a longer shadow. Press slaps it to 0.94 with a spring back. Big stickers lift a corner in 3D instead.</Rule>

## The vocabulary

| Moment | Motion | Where |
|---|---|---|
| Hover | **Peel**: lift, straighten, grow | Every interactive sticker (`peel`) |
| Press | **Slap**: squash to 0.94, spring back | Same |
| Commit | **Land**: a small sticker arrives from 1.3× and rotated, settles at −4° | Check, radio, selected day, filled OTP slot |
| Undo | **Peel off**: lifts, rotates, fades | Uncheck, remove a file |
| Open | **Drop in**: falls 14px with a slight rotate, settles | Dialogs, menus, popovers, toasts, tab panels |
| Close | **Lift out**: rises and fades fast | Same |
| Arrive | **Intro**: blocks drop 12px into place, 40ms apart; loose stickers also tumble in | A page on a hard load (`intro-page`), sections as they scroll in (`Reveal`), sticker groups (`Intro`) |
| Route change | **Snap**: the new page snaps in from the right, overshoots 4px, settles (260ms) | Every in-app navigation (`PageTransitions`) |
| Celebrate | **Burst**: voxel stickers pop and tumble (three.js) | Real milestones only |

## Page changes and intros

Route changes have to feel instant, so nothing ever waits on an exit animation. Your router swaps the page right away, and the new page snaps in from the right, overshoots by 4px and settles, like a sticker slapped down. Three pieces from [Page Transitions](/docs/components/page-transition) do this:

- **`PageTransitions`** goes in your providers with the current route. Every route change slides: links, `router.push`, back and forward, and jumps between layouts.
- **`PageSheet`** marks the part that slides. It is optional: without one, the page's `<main>` slides. The header and sidebar stay where they are.
- **`intro-page`** on a page's content drops its blocks in on a hard load. After an in-app navigation the slide carries the change, so the page doesn't animate twice. **`Intro`** (always) and **`Reveal`** (when it scrolls into view) stagger loose stickers; add `tumble` for small ones.

Intros never rotate blocks or text, only small loose stickers, so nothing pokes past the page edge.

## Timing

- **Peel spring**: `cubic-bezier(.3, 1.7, .5, 1)` over 260ms. The overshoot *is* the personality. Use `ease-peel` in Tailwind.
- **Overlays**: out-expo `cubic-bezier(.16, 1, .3, 1)` over 320ms (`ease-out-expo`).
- **Pixel things** (spinners, progress fills, XP blocks): `steps()`, so they move like sprites, not like video.

## Celebrate proportionally

A save should feel certain, not like a party. Bursts and big animations are for moments that cost the user real effort: submitting a project, finishing registration, winning a round.

<Rule name="Still">Under prefers-reduced-motion, peel tilt, flutter and bursts stop. State changes become instant colour swaps. The resting tilt of stickers may stay, because it isn't motion.</Rule>

pixel3d-ui handles reduced motion globally in the material CSS and inside every 3D component. If you add your own animation, use transform and opacity, and test with the OS setting on.
